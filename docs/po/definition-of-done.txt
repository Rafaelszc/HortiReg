================================================================================
                    DEFINITION OF DONE (DoD) - HORTIREG
================================================================================
Projeto: HortiReg · Gerência de Projetos (UEPB, 2026.2)
Equipe: Nidlan Hendell, Rafael e Julio Araújo

A Definition of Done estabelece as condições mínimas e obrigatórias para que uma história
de usuário seja considerada concluída (Done) pela equipe de desenvolvimento e aceita pelo PO.

--------------------------------------------------------------------------------
1. CRITÉRIOS NO NÍVEL DE HISTÓRIA DE USUÁRIO (USER STORY)
--------------------------------------------------------------------------------
[x] Código-fonte implementado conforme os requisitos e critérios de aceite descritos em Gherkin.
[x] Padrão de código e linters validados (Ruff para Python, ESLint/Prettier para React).
[x] Testes automatizados escritos e passando (testes unitários e de integração com pytest).
[x] Cenários de teste end-to-end ou de aceitação validados (Cypress/pytest-bdd).
[x] Pull Request aberto referenciando a chave da história no Jira.
[x] Revisão de código (Code Review) aprovada por pelo menos 1 membro da equipe (seguindo o rodízio).
[x] Pipeline de CI verde no GitHub Actions (build e testes 100% aprovados).
[x] Validação funcional realizada pelo QA (Julio Araújo na R1 / Rafael na R2).
[x] Aceite formal realizado pelo Product Owner (Nidlan Hendell na R1 / Julio Araújo na R2).

--------------------------------------------------------------------------------
2. CRITÉRIOS NO NÍVEL DE RELEASE
--------------------------------------------------------------------------------
[x] Todas as histórias da release em estado "Concluído" no Jira.
[x] Nenhum bug de severidade crítica ou alta em aberto.
[x] Build dos contêineres Docker gerando imagens funcionais sem falhas.
[x] Documentação e Release Notes da versão atualizadas e publicadas.
[x] Demonstração das funcionalidades realizada com sucesso para o cliente/docência.
